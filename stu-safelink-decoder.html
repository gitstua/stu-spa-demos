What this page does

Why now? On 13 November 2026 Microsoft had a global Microsoft 365 outage lasting more than 12 hours, mainly affecting access to Exchange Online, with Teams, SharePoint Online and Microsoft Defender XDR also listed as possibly affected (iTnews: "Microsoft users caught up in global M365 outage"). When Microsoft's infrastructure is struggling, Safe Links can stall too, so links in emails you've already received may hang or show errors. This page doesn't need any Microsoft service: it reads the real destination straight out of the link, so you can still get to the pages your emails point to.

Microsoft 365 rewrites links in email and Teams messages so they go through a Defender for Office 365 "Safe Links" scanner first, e.g. https://aus01.safelinks.protection.outlook.com/?url=…&data=…&sdata=…&reserved=0. When that service is degraded, clicking the link just hangs or errors — but the real destination is sitting right there inside the url query parameter.

  • Decoding: every URL on a *.safelinks.protection.outlook.com host (plus the Teams statics.teams.cdn.office.net/…/atp-safelinks.html variant) is parsed with the browser's URL API and its url parameter is URL-decoded. Nested / double-wrapped safelinks are unwrapped repeatedly.
  • Metadata: the data parameter is a pipe-separated blob (version, recipient mailbox, a message GUID, tenant ID, timestamp…). It's split and shown for curiosity — it is not needed to reach the destination.
  • Privacy: nothing leaves your browser — no network requests are made and the destination is never visited for you. Input is only written to the URL fragment (#) if you tick "Keep input in URL", since the data field can contain your email address.
  • Safety: Safe Links exists to catch phishing. Bypassing it means you are the scanner — check the highlighted host name carefully before opening anything.
